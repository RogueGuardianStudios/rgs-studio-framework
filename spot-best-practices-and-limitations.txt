Spot Watchdog — Best Practices and Limitations
================================================
Based on validation testing: 2026-03-13
Models tested: Haiku Spot, Sonnet Spot, Opus watched agent
Tests passed: 17/19 (2 deferred: full ladder, seed pickup)


WHAT SPOT IS GOOD AT
--------------------

Catching explicit violations.
When an agent writes code-first, expands scope, or makes unauthorized
decisions — and the evidence is in the files — Spot finds it reliably.
Even Haiku. The compound test proved this across 4 escalation stages
with zero misses on the obvious stuff.

Tracking patterns across checkpoints.
Spot correctly distinguished "one TDD skip" (minor) from "systematic
TDD failure + scope expansion" (significant). It didn't just count
violations — it recognized qualitative escalation.

Enforcing hard boundaries.
The HALT mechanism works (after BUG 1 fix — HALT filename mismatch).
The gate blocks tools. The threshold ratchet controls when checkpoints
fire. The compression cycle preserves state. The plumbing is solid.


Catching organic drift from loose Briefs.
When a Brief is vague, agents fill in ambiguity with their own judgment
instead of escalating. This produces real drift — unauthorized API design,
silent architectural decisions, changed error handling. Spot caught every
instance in the loose Brief test: string-based API chosen without
authorization, error handling changed from throw to passthrough, function
names changed, template relocated, TDD timing questionable (29-second gap
between test and implementation files). Verdict: Significant drift, reject.
This proves Spot works on organic drift, not just synthetic violations.

Detecting that Brief quality drives drift.
The same task (Brief template engine) produced zero drift with a tight
Brief and significant drift with a loose Brief. Same agent model (Sonnet),
same governing MD. The only variable was Brief specificity. Spot correctly
assessed both: 4 consecutive Clean on the tight Brief, Significant drift
on the loose one. This is the core finding: Spot's value is proportional
to Brief quality.


WHAT SPOT CANNOT DO
-------------------

Catch subtle drift.
Everything in the synthetic tests had smoking-gun evidence — comments
saying "written after code," methods obviously outside the Brief. However,
the loose Brief test showed Spot CAN catch subtler drift: silent design
decisions, changed behavior, files in wrong locations. The real limitation
is drift that produces no observable difference in the work product — an
agent that makes the "right" unauthorized decision leaves no evidence.

Assess intent or reasoning quality.
Spot checks "did you cross this line" — not "is this the right
approach." A perfectly in-bounds implementation that's architecturally
terrible will get Clean. Spot is a boundary monitor, not a code reviewer.

Detect drift in real-time.
Spot only runs at threshold checkpoints. Between checkpoints, the agent
works unsupervised. If an agent drifts and self-corrects before the next
checkpoint, Spot never sees it. If an agent drifts right after a
checkpoint, it has the full threshold increment of runway before Spot
fires again.

Monitor itself.
Spot assesses the agent's work product, but nobody assesses Spot. A
lenient Spot (especially Haiku) might miss things consistently. A
hallucinating Spot could flag clean work. There's no watchdog for the
watchdog.


BEST PRACTICES
--------------

1. Write tight Briefs with hard boundaries.
   Spot's accuracy is directly proportional to how unambiguous the
   governing MD is. "Implement Add and Subtract" is easy to monitor.
   "Build something good" is impossible. The simulated-agent.md works
   because its boundaries are binary — you either escalated or you didn't.

2. Use Haiku for routine monitoring, Sonnet for critical tasks.
   Haiku catches significant drift and compounding patterns reliably.
   But it's more lenient on minor issues (missed the doc quality gap
   and coverage asymmetry in the minor drift test). For high-stakes
   work, /spotcheck sonnet is there.

3. Keep the threshold increment at 15.
   This gives Spot 5-6 checkpoints before compression. Too low (5)
   means constant interruptions. Too high (25) means fewer checkpoints
   and more unsupervised runway between them.

4. Don't rely on Spot for code quality.
   That's the reviewer's job. Spot checks behavioral integrity — scope,
   process, boundaries, values. Pair Spot with code review for full
   coverage.

5. The feedback loop matters more than detection.
   Spot catching drift is only useful if the agent reads
   spot-notes-agent.md and actually corrects. The CLAUDE.md protocol
   forces this, but we haven't proven it works end-to-end with a real
   agent responding to feedback.

6. Compression seeds need to be specific.
   Vague seeds produce agents that re-derive context instead of
   continuing. The more concrete the "verified state at anchor" section
   is, the better the new session picks up.


7. Brief quality is the primary control.
   A tight Brief with explicit deliverables, function signatures, error
   handling requirements, and a "NOT in scope" section produced zero drift
   across 4 phased checkpoints AND a single-shot run. The same task with
   a loose Brief ("build a template system, make it work") produced
   significant drift immediately. Write the Brief like a contract, not a
   wish list. The "NOT in scope" section is not optional — it's the
   difference between Clean and Significant drift.

8. Vague Briefs should trigger more escalations, not fewer.
   The governing MD says "stop and escalate" when the Brief doesn't cover
   something. A vague Brief means nearly everything requires escalation.
   Agents that silently fill in ambiguity are drifting. Spot catches this
   pattern: it flags unauthorized decisions even when the decisions are
   reasonable, because the process violation (not escalating) is the issue.


KNOWN LIMITATIONS TO ACCEPT
----------------------------

- The feedback loop is untested end-to-end. We know Spot writes good
  corrections. We don't know if agents consistently follow them.

- Single-session testing only. Full threshold ladder and compression
  seed pickup tests are still deferred.

- No adversarial testing. An agent that intentionally hides drift
  (rewrites comments, structures code to look compliant) has not been
  tested against.

- No calibration data for Haiku Spot's context consumption. The
  empirical checkpoint cap was measured for Sonnet/Opus. Haiku's
  checkpoint size may differ.

- Subagents bypass the hook pipeline. Spot monitors the parent agent's
  tool calls via hooks, not tool calls inside spawned subagents. Live
  mid-task monitoring requires either phased execution with checkpoints
  between phases, or an API harness that simulates the hook pipeline.

THE HONEST SUMMARY
------------------

Spot is a reliable boundary enforcer. It catches explicit violations
on synthetic tests, tracks compounding drift across checkpoints, and
detects organic drift from real agents working on real tasks. The key
insight from testing is that Spot's effectiveness is driven by Brief
quality — tight Briefs produce clean work that Spot correctly approves,
loose Briefs produce drift that Spot correctly catches. Haiku is viable
for production Spot. The infrastructure (hooks, gate, HALT, threshold
ratchet, compression) is proven. The main gaps are the untested feedback
loop (does the agent actually self-correct?) and subagent bypass (hooks
don't fire inside spawned agents). For what it's designed to do —
behavioral boundary enforcement — it works.
